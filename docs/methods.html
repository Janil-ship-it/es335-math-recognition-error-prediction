Which Handwritten Math Lines Can We Trust?

Pipeline, features, models, and evaluation design

Pipeline

  1. Capture check — flag blank, cut-off or extremely blurry pages (reported, not silently dropped).
  2. Region extraction — line-level crops via horizontal projection + adaptive threshold (OpenCV). Manual correction allowed in v1.
  3. Light cleaning — grayscale, denoise, contrast stretch, deskew, pad/resize.
  4. Recognition — pre-trained HMER model (TexTeller / UniMERNet candidates). Inference only, never fine-tuned. Returns LaTeX + per-token confidences.
  5. Feature extraction — image quality, confidence statistics, structure counts from predicted LaTeX.
  6. Error prediction — classical models rank regions by P(needs_correction).
  7. Human review — top-k by predicted risk at a fixed budget; remaining lines keep recogniser output.
Development note. The current submission uses a carefully designed synthetic proxy whose feature–error relationships follow documented HMER failure modes. The same code path is reused when real scans arrive. Real HMER weights are optional and blocked without GPU/model download.

Features (allowed at prediction time)

GroupFeatures
Confidencemean token confidence, min token confidence, output length
Image qualityblur (Laplacian), contrast, ink density, stroke width, skew, crop size, background noise
Structurecounts of fractions, powers, roots, subscripts in predicted LaTeX

Forbidden: reference text, marks, student ID, group ID, question ID.

Models

  • Fixed confidence threshold (baseline) — ranks by mean or min token confidence (chosen on training folds).
  • Logistic regression (L2) — standardised features, class-balanced weights in training only.
  • Random forest — shallow trees (depth ≤ 4), bootstrap aggregation.
  • SVM (RBF) — scikit-learn SVC + sigmoid calibration via CalibratedClassifierCV.

Selection rule: simplest model whose validation PR-AUC is within one standard error of the best (grouped CV).

Evaluation design (fixed before model comparison)

  • Split by student/writer group only. ~20% groups held out as test; never used until final evaluation.
  • Development set: 5-fold grouped cross-validation.
  • Primary metric: PR-AUC.
  • Operational metrics: recall of true errors at 20%, 30%, 50% review budgets; residual symbol-error rate after simulated correction.
  • Uncertainty: paired bootstrap over test students (2 000 resamples, 95% intervals) for metrics and for Δ vs baseline.
  • Integrity: shuffled-label control; no leakage through forbidden features or region-level splits.

Labelling & normalisation

References are human transcriptions. Before comparison we normalise spacing and equivalent commands (\leq→\le, etc.). Every normalisation rule has a unit test. The recogniser output is never copied into the reference.
