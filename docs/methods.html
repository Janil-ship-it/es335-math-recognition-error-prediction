Methods

Pipeline, models, and evaluation design fixed before comparison

Synthetic development data ES 335 · IITGN
In short. Grouped 5-fold CV on development students only. Primary metric is PR-AUC. Test students are scored once after models are frozen. Uncertainty is student-level bootstrap.

Pipeline

  1. Capture check and line-level region extraction (OpenCV projection baseline).
  2. Light cleaning: grayscale, denoise, contrast stretch.
  3. Recognition: pre-trained HMER (inference only). Development path uses a proxy backend.
  4. Features: confidence statistics, image quality, structure counts from predicted LaTeX.
  5. Flagger ranks by P(needs_correction); top fraction goes to human review.

Models

  • Fixed confidence threshold (baseline) — rank by mean or min token confidence (chosen on train folds).
  • Logistic regression (L2) — standardised features, class weights in training only.
  • Random forest — shallow trees (depth ≤ 4).
  • SVM (RBF) — calibrated probabilities via CalibratedClassifierCV.

Selection rule: simplest model within one standard error of the best validation PR-AUC.

Evaluation design

  • Split by student/writer group only (~20% groups held out as test).
  • Development: 5-fold grouped CV; never touch test for tuning.
  • Primary metric: PR-AUC. Operational: recall of errors at 20%, 30%, 50% review budgets; residual SER.
  • Uncertainty: paired bootstrap over test students (2 000 resamples, 95% intervals).
  • Integrity: shuffled-label control; no forbidden features.
