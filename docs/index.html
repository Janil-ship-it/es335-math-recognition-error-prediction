Which Handwritten Math Lines Can We Trust?

Predicting recognition errors so only risky handwritten-math lines go to human review

1. Research question

After a pre-trained recogniser turns a student’s handwritten math into LaTeX, which lines are likely wrong, so a marker only reviews those and trusts the rest?

Success means: at the same review budget (20%, 30%, or 50% of lines), a learned flagger catches more true errors than a fixed confidence-threshold baseline. A modest or negative result is acceptable and is reported honestly.

What one row is

One region = one cropped line of handwritten math + the recogniser’s LaTeX for that line. The label needs_correction = 1 if the normalised predicted LaTeX differs from the normalised reference; else 0. We never predict marks or student identity—only “should a human check this line?”

  • Prediction time: right after recognition, before grading
  • Allowed inputs: image-quality features, token confidences, structure counts from the predicted LaTeX
  • Forbidden inputs: reference text, marks, student ID, question ID

2. Data

Source

Plan A was anonymised course scripts (scans + human-checked LaTeX) from the course instructor. Those were not available at build time. We therefore built a development proxy whose feature–error relationships follow documented handwritten-math recogniser failure modes (blur, low contrast, complex structure raise error risk; high token confidence lowers it). When real scans arrive, the same code path is reused unchanged.

Key variables

  • Image quality: blur, contrast, ink density, stroke width, skew, crop size, background noise
  • Confidence: mean token confidence, min token confidence, output length
  • Structure: counts of fractions, powers, roots, subscripts in the predicted LaTeX
  • Label: needs_correction (binary); SER (symbol error rate) for residual-error reporting

Quality issues

  • Proxy data is not real course handwriting—results describe the method, not yet operational performance on IITGN scripts.
  • Error rate is high (~60%) by design of the proxy (stress-tests ranking under many errors).
  • Only six test groups → wide uncertainty intervals.

3. Preprocessing choices

  • LaTeX normalisation before labelling: strip whitespace, map a few equivalent commands (\leq→\le, etc.). Spacing-only differences are not counted as errors.
  • Group-level split (by student ID), fixed in data/splits.json with seed 42 before any modelling. No region from a test student appears in training.
  • Standardisation of features inside logistic regression and the forest (train-set mean/std only).
  • No leakage features: reference LaTeX, marks, and IDs are never used as model inputs (enforced in config).

4. Baseline and models

MethodWhat it usesRole
Confidence thresholdMean or min token confidence (chosen on train folds)Primary baseline: rank by “how unsure the recogniser was”
L2 logistic regressionAll allowed features, class-balanced, L2 penaltySimple learned flagger; interpretable coefficients
Random forestBagged shallow trees on feature subsetsNon-linear alternative; capacity controlled by depth

Model selection used grouped 5-fold CV on development students only, with the one-standard-error rule on validation PR-AUC. Logistic won on development; both logistic and forest are reported on the test set.

5. Evaluation design

  • Split: 22 students train/dev, 6 held out for a single final test. Test touched only in 05_evaluate_test.py.
  • Primary metric: PR-AUC (ranking quality under imbalance).
  • Operational metrics: recall of true errors at fixed review rates 20%, 30%, 50%; residual average SER after “fixing” the top-rate fraction.
  • Calibration: Brier score.
  • Uncertainty: paired bootstrap over test students (2000 resamples), including Δ vs baseline.
  • Integrity: shuffled-label control (train on permuted labels) → PR-AUC near prevalence if no leakage.

With only six test students the bootstrap intervals for the gains still include zero, so we do not claim a statistically stable win yet—we report the uncertainty. 7. Error analysis

At a 30% review budget, the baseline still misses about 64% of true errors; logistic misses about 58%. Misses tend to be cases where confidence looked moderate but image quality or structure was hard (high blur / complex fractions)—exactly the regimes the learned model is meant to catch using non-confidence features.

False alarms waste marker time; at equal review rate the ranking trade-off is built into PR-AUC and recall@k. Residual SER after reviewing the top 30% falls from ~0.13 (baseline) to ~0.12 (logistic), consistent with slightly better targeting of high-SER mistakes.

9. Limitations and claims

  • Proxy data: Not real course scans. We claim a working evaluation methodology and ranking gains under this recogniser behaviour—not operational accuracy on IITGN scripts until Plan A is run.
  • Small test set: Six groups → wide CIs; deltas vs baseline are not yet significant at 95%.
  • One recogniser profile: Real TexTeller/UniMERNet confidences may shift the operating point.
  • High base error rate: Makes ranking easier than on a cleaner recogniser; results may shrink when recognition improves.

What we do claim: On this setup, logistic and forest improve PR-AUC and error recall at fixed review budgets relative to a confidence threshold, with uncertainty quantified by student-level bootstrap, and with a negative control that does not look like leakage.
