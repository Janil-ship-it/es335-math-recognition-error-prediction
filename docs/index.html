Which Handwritten Math Lines Can We Trust?

Predicting recognition errors so only risky handwritten-math lines go to human review

Research question

After a pre-trained recogniser turns a student’s handwritten math into LaTeX, which lines are likely wrong, so a marker only reviews those and trusts the rest?

Success is not accuracy. Success is: at the same human review budget (20 %, 30 %, or 50 % of lines), does a learned flagger catch more true errors than a fixed confidence-threshold baseline?

A modest or negative result is acceptable and is reported honestly.

Key takeaway (held-out test groups)

Learned models improve PR-AUC and error recall at fixed review budgets relative to a pure confidence threshold. With only six test students the bootstrap intervals for the gains still include zero, so we do not claim a statistically stable win yet — we report the uncertainty.

What one row is

One region = one cropped line of handwritten math + the recogniser’s LaTeX for that line. The label needs_correction = 1 if the normalised predicted LaTeX differs from the normalised reference; otherwise 0. We never predict marks or student identity — only “should a human check this line?”

  • Prediction time: right after recognition, before grading
  • Allowed inputs: image-quality features, token confidences, structure counts from the predicted LaTeX
  • Forbidden inputs: reference text, marks, student ID, question ID

Why this matters

Grading handwritten maths with an AI model is costly partly because the same scanned page may be read again and again. Our idea is to read each handwritten line once, turn it into text, and use a small machine-learning model to guess which lines the reader probably got wrong. Only those risky lines go to a person for correction. The rest are trusted, so later grading and rechecking can start from the stored text instead of re-reading the image.

What changed since the first proposal. Our first proposal was about reading bubble sheets. That step already runs locally without a language model, and language-model effort goes mainly into the handwritten answers. Prof. Bhatia suggested digitising handwritten working at the point of capture and using machine learning to flag unreliable readings. This project follows that suggestion.
