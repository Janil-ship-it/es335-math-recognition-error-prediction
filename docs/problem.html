Problem

What we are trying to predict — and what we refuse to use as input

Synthetic development data ES 335 · IITGN
In short. After a pre-trained recogniser turns a handwritten math line into LaTeX, we predict which lines are likely wrong so a marker only reviews those. Success is higher error recall at the same review budget — not accuracy.

Research question

At the same human review budget (20%, 30%, or 50% of lines), does a learned flagger catch more wrong recogniser readings than a fixed confidence-threshold baseline?

A modest or negative result is acceptable and is reported honestly.

What one row is

One region = one cropped line of handwritten math + the recogniser’s LaTeX for that line. The label needs_correction = 1 if the normalised predicted LaTeX differs from the normalised reference; otherwise 0.

  • Prediction time: right after recognition, before grading
  • Allowed inputs: image-quality features, token confidences, structure counts from predicted LaTeX
  • Forbidden inputs: reference text, marks, student ID, question ID

Why this matters

Grading handwritten maths with an AI model is costly partly because the same scanned page may be re-read many times. The idea is to read each line once, store text, and use a small model to guess which lines the reader probably got wrong. Only those lines go to a person.
